# SAFE_AGGRESSIVE_FRONTIER — M02

This is a bounded future-work record, not authorization to implement another
transform. All profiles remain subject to full evidence and persistence guards.

| Class | Current reason for RAW/reduction | Safe aggressive candidate and required evidence |
|---|---|---|
| NOISE | Known finite boilerplate grammar already reduces with T01 in every mode/profile | Broaden real workload allowlists; keep positive reduction tests and protected-tail counterexamples |
| PROGRESS | Complete known progress grammar reduces in EXPLORE/BUILD | Richer progress adapters preserving first/last/state/error transitions; distinguish terminal redraws from event evidence |
| DISCOVERY | T01 lacks directory/list consumer contract, not universal irreducibility | Exact path-prefix dictionaries/tree layout reduction retaining all paths, types, counts and ordering |
| SUCCESS_SUMMARY | PASS records may be test identities or measurements | Future T03 only with exact counts, test identity/outcome and warnings; no aggregation on mixed failures |
| DIAGNOSTIC | Severity, occurrence and causal order are material | Separate proven boilerplate from verbatim diagnostics; preserve repeated event multiplicity/context |
| FAILURE | Failure content and chronology protected | Only separately established noise regions; never suppress failures or depend on RAW retrieval for diagnosis |
| CANONICAL_STATE | Exact canonical evidence protected | Consumer-specific representations with stable hashes, paths, statuses and order; no generic Git prettification |
| MACHINE_DATA | No approved compatibility contract; T04 deferred | Separate byte identity, lexical/parse/semantic equivalence and consumer compatibility before selecting an encoding |
| AUTHORITY | Permissions, signatures and decisions protected | No current safe generic frontier; any lossless proposal requires a specific authority-consumer proof |
| SECURITY | Security evidence protected independently of sensitivity | Non-sensitive scanner boilerplate could reduce with findings/locations/severity verbatim; credentials never persist |
| BENCHMARK | Measurements/units/provenance protected | Remove only proven presentation duplication while preserving every observation and comparison basis |
| UNKNOWN | No safe complete grammar established | Improve recognition from labeled workload evidence; do not relabel by repetition ratio or compression pressure |

Default/FioOS/FioIdeias currently share the hardened T01 eligibility. M01 FioOS
restrictions on discovery/diagnostics/success become relevant again only after
specific new transforms are independently approved. FioIdeias remains an
uncharacterized workload, not evidence for a broader policy.

M02 identified accidental over-conservatism in NOISE/PROVE: runtime contradicted
its stated allowance. This is fixed, with an assertion that genuine known noise
actually transforms in all profiles after a previous PROVE failure. Other RAW
classes above are recorded as contract work, not permanent blanket prohibitions.
